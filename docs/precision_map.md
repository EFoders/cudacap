# Precision map of the reference Fortran

Complete census of every non-default-precision declaration in
`reference/voacapl/src` (191 `.for`/`.f95`/`.hdr` files), generated by
grepping for `DOUBLE PRECISION` / `REAL*8` / `DBLE(` (case-insensitive,
comments excluded). This is the normative reference for dtype choices in the
port: **everything not listed here is `REAL*4` (Fortran default REAL) and is
ported as float32.**

> The `reference/` tree is no longer in the working tree (removed in commit
> `477dad7`). Restore it with `git checkout 477dad7^ -- reference`.

Notably, there are **zero** `DBLE(...)` promotions inside expressions
anywhere in the codebase — double precision appears only via the whole-scope
declarations below.

## Full double-precision scope (port as float64)

| File | Declaration | Why |
|------|------------|-----|
| `voacapw/dazel.for:3` | `IMPLICIT DOUBLE PRECISION(A-L,N-Y)` | Great-circle geometry; spherical-trig catastrophic cancellation for near-coincident points (header warns: unpredictable below 0.00005°, ~5 m, *even in double*) |
| `voa_lib/dazel1.for:3` | same | Same routine, mode-1 wrapper variant |
| `wp10dwin/dazel0.for:3` | same | Same routine, mode-0 wrapper variant |

Subtlety worth preserving: `IMPLICIT DOUBLE PRECISION(A-L,N-Y)` deliberately
excludes `M` (stays default INTEGER) and `Z` (stays default REAL*4). All the
interface variables are named `Z*` — so DAZEL takes single-precision inputs,
computes internally in double, and returns single-precision outputs. The port
must mirror exactly that: float32 at the boundary, float64 inside.

## REAL*8 fields in COMMON headers

| File | Fields | Notes |
|------|--------|-------|
| `voacapw/ficepac.hdr` | `montha(10)`, `qindexa(10)` | REAL*8 among otherwise REAL*4 neighbors — month/Q-index arrays passed from the GUI-side interface |
| `voacapw/fice_ssn.hdr` | `flat(5)`, `flon(5)`, `fof2(5)` | Station coordinate / foF2 table (`ssn_eff`, `ssn_ave` in the same header stay REAL*4) |

`voacapw/voacapw.for:123` has a commented-out `real*8 start_time,end_time`
(dead code, ignored). `voacapw/ficearea.hdr`, `ficearea`/`fice_ssn` REAL*4
fields, and `inmuf.for`/`virtim.for` REAL*4 declarations are explicit
single-precision declarations — i.e. the default, listed in grep output only
because they name `REAL*4` explicitly.

## Port rule of thumb

1. Default dtype: float32, narrowed at every assignment (Fortran REAL*4
   semantics — intermediate expression evaluation width is compiler-dependent,
   but gfortran at `-O2` without `-ffast-math` evaluates REAL*4 arithmetic in
   single precision; Stage A must narrow with `np.float32` per operation).
2. float64 only for the scopes/variables tabled above.
3. Where float64 internals meet float32 interfaces (DAZEL's `Z*` variables),
   convert exactly at the boundary the Fortran does, in the same direction.
